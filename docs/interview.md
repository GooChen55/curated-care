# 技术讲解

项目定位：基于 Java 电商业务与 Python 售后助手的购物服务平台。演示一次从下单到审核退款的完整链路，再解释接口、状态和事务如何保证结果可靠。

1. 职责边界：Java 决定身份、订单归属、金额与状态；助手调用认证后的业务接口。
2. 写入确认：退款需要收集原因和明确确认，模型只能选择白名单意图。
3. 幂等：订单的用户＋请求键、退款的订单唯一约束、聊天的用户＋消息键以及审核状态检查。
4. 库存并发：固定顺序行锁、事务库存校验、并发最后一件商品测试。
5. 流程恢复：任务上下文、暂停栈、SQLite 持久化和显式恢复。
6. 知识质量：片段来源、引用、无依据拒答，真实模型效果需通过评测集测量。
7. 工程组织：统一前端、三个职责明确的服务、共同契约、启动脚本、测试和部署。

讲解范围以实际代码、测试和本人理解为依据。演示支付/物流、单 worker 与尚未验证的模型质量需要如实说明；不要使用未经测量的吞吐量、准确率或用户规模。
